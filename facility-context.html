현재 반영 중인 시설 정보

현재 HMI와 디지털 트윈 프로토타입은 온실의 기본 형태와 배치 정보를 중심으로 시설을 표현합니다. 이 정보는 고객 화면에서 온실을 이해하기 쉽게 보여주고, 센서·작동기 위치를 시각화하는 데 사용됩니다.

온실 기본 구조

  • 온실 타입: 유리온실, 연동 비닐하우스, 단동 비닐하우스
  • 작물 종류
  • 길이, 폭
  • 동 수, 동 간격
  • 스팬 수
  • 방위와 북쪽 보정각

공간·장비 배치

  • 지도 기반 온실 위치와 회전
  • 재배 베드 수와 방향
  • Air, CO2 센서 위치
  • FR, SW, Hub 등 기본 장비 위치
  • 고객 화면용 평면도와 3D 표현

개선해야 할 사항

AI 분석이 더 정확해지려면 단순한 온실 크기 외에도 실제 구조, 피복, 환기, 커튼, 난방, 관수 설비가 시설 컨텍스트로 함께 관리되어야 합니다. 아래 항목은 우선적으로 추가해야 할 시설 스펙입니다.

구조 치수

  • 측고
  • 동고
  • 처마고
  • 천고
  • 지붕 형태와 경사

피복·단열 조건

  • 피복재 종류: 유리, PO, PE, PC 등
  • 피복 층수: 1중, 2중 등
  • 방풍: 1중, 2중
  • 피복 노후도 또는 교체 시점

환기·개폐 구조

  • 천창 개폐 방식
  • 측창 개폐 방식
  • 1단/2단 개폐 여부
  • 권취, 랙 방식 등 구동 방식
  • 구역별 개폐 가능 여부

커튼·차광 설비

  • 측면 다겹보온커튼
  • 수평 다겹보온커튼
  • 스크린
  • 차광망
  • 커튼 구역과 개폐 방향

순환·환기 설비

  • 순환팬 수량
  • 순환팬 배치 라인
  • 대형확산팬 또는 제트팬
  • 강제 환기 장치
  • 장비 그룹과 제어 구역

주요 설비 스펙

  • 난방기 또는 보일러
  • CO2 공급 설비
  • 관수·양액 설비
  • 포그 또는 미스트 설비
  • 펌프, 밸브, 탱크, 배관 구역

현재 AI 오케스트레이션 방식

현재 문서화된 MESH AI 흐름은 앱에서 작물 이미지와 시설 식별자를 전달하고, AI 서버가 백그라운드에서 여러 분석 도구를 순차 실행한 뒤 결과를 폴링으로 반환하는 구조입니다. 리포트 생성과 규칙 변경 승인은 별도 단계로 분리할 수 있습니다.

1. 분석 요청

  • 앱에서 작물 이미지와 `facility_id`를 전송
  • 필요 시 `env_id`를 함께 전달
  • 서버는 즉시 `task_id`를 반환하고 백그라운드 분석 시작

2. 도구 분석

  • 센서 히스토리 조회
  • 작물 이미지 분석
  • 발병·환경 위험도 평가
  • 작동기 목록과 현재 상태 조회
  • 환경 예측과 제어 추천 생성

3. 결과 폴링

  • 앱은 `task_id` 기준으로 분석 상태를 반복 조회
  • 도구별 결과가 완료되는 순서대로 누적
  • 최종 권고, 충돌 분석, 위험 요인을 UI에 표시

4. 선택 단계

  • 도구 결과 기반 AI 종합 리포트 생성
  • 제어 규칙 변경 제안
  • 사용자 승인 후 운영 서버에 규칙 반영

현재 구조에서 보이는 개선 포인트

현재 흐름은 `facility_id`를 중심으로 데이터를 묶는 구조입니다. 다음 단계에서는 시설 스펙을 단순 조회 정보가 아니라 각 분석 도구의 공통 컨텍스트로 주입하는 레이어가 필요합니다.

시설 컨텍스트 조회 레이어

  • `facility_id` 기준으로 `facility_spec`을 먼저 조회
  • 센서 히스토리, 작동기 목록, 시설 스펙을 하나의 분석 컨텍스트로 구성
  • 컨텍스트 생성 시 누락 필드와 신뢰도를 함께 반환

도구별 입력 확장

  • 위험도 평가에 피복, 측고, 커튼, 환기 조건 반영
  • 환경 예측에 온실 체적, 환기 구조, 팬 그룹 반영
  • 제어 추천에 실제 설비 존재 여부와 제어 구역 반영

장비 그룹 매핑

  • 개별 장비를 순환팬 라인, 커튼 구역, 천창/측창 그룹으로 묶기
  • 그룹별 상태, 수량, 제어 가능 여부를 별도 관리
  • 고객 화면은 그룹 중심, 관리자 화면은 개별 장비 중심으로 표시

분석 추적성

  • AI 권고가 어떤 시설 스펙을 참조했는지 기록
  • 누락된 시설 정보가 있으면 보수적 권고로 전환
  • 권고 결과에 사용된 데이터 시점과 컨텍스트 버전 표시

AI 파이프라인 연결 예시

구현 시에는 분석 요청 직후 공통 컨텍스트를 만들고, 이후 도구들이 같은 컨텍스트를 참조하도록 구성하는 방식이 적합합니다. 

submit_analysis(image, facility_id, env_id)
  -> create_task(task_id)
  -> build_facility_context(facility_id)
       - facility_spec
       - sensor_history
       - actuator_groups
       - current_actuator_status
       - missing_context_fields
  -> run_crop_image_analysis(image, context)
  -> run_event_risk_check(context)
  -> run_environment_prediction(context)
  -> run_control_recommendation(context)
  -> run_final_recommendation(context, tool_results)
  -> optional_report(tool_results, context)
  -> optional_rule_proposal(context, approved_by_user)

적용 로드맵

1. 관리자 입력 시설 기본 정보에 구조·피복·설비 항목을 추가합니다.
2. 장비 그룹화 순환팬, 커튼, 천창, 측창, 관수 설비를 그룹 단위로 묶습니다.
3. 컨텍스트 빌더 분석 시작 시 시설 스펙, 센서 이력, 장비 그룹을 하나로 묶습니다.
4. AI 도구 확장 위험도, 예측, 제어 추천 도구가 같은 시설 컨텍스트를 참조하게 합니다.
